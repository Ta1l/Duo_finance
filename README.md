# 🤖 Дуэт-финансист — бот парного учёта финансов

Telegram-бот для двух друзей/партнёров: ежедневный учёт доходов-расходов,
гашение долгов наперегонки, копилка «в пути» с выплатой по четвергам,
стрики и воскресные соревновательные отчёты.

**Стек:** Python 3.11+ · aiogram 3.x · SQLAlchemy 2.x (async) + SQLite (легко
переключается на PostgreSQL) · APScheduler 3.x.

---

## Быстрый старт

```bash
cd duo_finance
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # вставить BOT_TOKEN от @BotFather
python bot.py
```

Затем **оба игрока** пишут боту `/start`: первый становится Игроком A, второй — второй
становится Игроком B, третьему бот откажет. Стартовый долг задаётся переменной
`START_DEBT` (по умолчанию 300 000 ₽).

## Сценарий дня (23:30 МСК)

Планировщик шлёт всем, кто ещё не заполнил отчёт за сегодня, FSM-диалог:

1. **Приход на карту** → число ≥ 0
2. **Расходы** → число ≥ 0 (форматы: `1500`, `2450.50`, `1 234,56`)
3. **Заработано «в пути»** → число ≥ 0
4. **В счёт долга** → число ≥ 0 **или reply-кнопка «Пропустить (0)»**
   → debt_paid = 0, остаток долга не меняется.

После сохранения: сводка дня, новый остаток долга, статус стрика.
`/cancel` — прервать; `/report` — заполнить/перезаписать вручную
(перезапись через inline-подтверждение, история пересчитывается от источника).

`/editday` показывает кнопки от понедельника текущей недели до сегодняшнего дня.
Можно добавить пропущенный отчёт или полностью перезаписать существующий через тот
же опрос из четырёх шагов. Учёт начинается 10.08.2026 (день 1); прошлая неделя и
будущие даты недоступны.

## Формулы (services/)

| Показатель | Формула | Где |
|---|---|---|
| Остаток долга | `debt_start − Σ(debt_paid)` (≥ 0, пересчёт от истории — устойчив к перезаписям) | `crud.recompute_debt` |
| Копилка недели | `transit_pool_week = Σ(in_transit_earned)` за Пн–Вс | `crud.week_totals` |
| Средний платёж | `Σ(debt_paid за N дн.) / N`, N=14 (env) | `services.calculations.avg_over_days` |
| ETA свободы | `ceil(debt_current / avg)`; avg=0 → «не определено» | `services.calculations.eta_days` |
| Воскресные средние | недельные суммы / 7 (расходы, «в пути», карта) | `weekly_report` |
| Стрик | дни подряд с `in_transit_earned > 0`; 0 ₽ или пропуск дня → 0 | `crud.recalc_streak` |

## Цикл денег «в пути»

- Учётное окно: **Пн 00:00 — Вс 23:59 МСК**.
- Заработок недели **не** падает на карту сразу — выплата в **следующий четверг**.
- **Чт 09:00 МСК**: «Сегодня четверг! Твоя сгораемая копилка за прошлую неделю
  превратилась в реальные деньги: +X ₽!» (идемпотентно — ключ `payout:<ISO-неделя>`).
- **Пн 00:00 МСК**: уведомление о старте новой недели. Сам счётчик обнуляется
  сам собой: `transit_pool_week` всегда считается как Σ за текущее окно Пн–Вс
  прямо из отчётов (единый источник истины), хранить «живой» счётчик не нужно.

## Воскресная синхронизация (Barrier Lock)

1. Вс 23:30 оба получают опрос.
2. Первый заполнивший получает: «Твой отчёт зафиксирован! Ждём, пока
   **[партнёр]** заполнит данные…»
3. Как только **оба** внесли данные за воскресенье — мгновенный
   **Соревновательный отчёт** обоим (одинаковый текст, честно):
   - 🏆 «Мастер Заработка» (больше в копилку), 💳 «Мастер Карты» (больше приход),
     🛡️ «Бережливый года» (меньше расходов), ничьи — 🤝;
   - средние за день за неделю;
   - внесено в долг за неделю, остаток долга, прогноз свободы;
   - бонус: текущие стрики.
4. От одновременной двойной генерации защищает `asyncio.Lock` + ключ
   `weekly_report:<ISO-неделя>` в таблице `meta` (переживёт перезапуск бота).

## Осознанные проектные решения

- **Жёсткая пара**: ровно 2 слота (`A`/`B`); посторонним — отказ уже в middleware.
- **Перезапись отчёта** не ломает математику: долг и стрик пересчитываются от
  таблицы отчётов, а не инкрементально.
- **Идемпотентные рассылки**: пейауты и итоги недели помечаются в `meta`, бот
  можно перезапускать в любой момент без дублей.
- **Приватность по умолчанию**: незарегистрированный пользователь кроме `/start`
  ничего не может.
- **День отчёта фиксируется при старте опроса**: начал в 23:30, закончил в 00:05 —
  отчёт ляжет на «вчера», как и задумано.

## Продакшн-заметки

- **PostgreSQL**: `DATABASE_URL=postgresql+asyncpg://user:pass@host:5432/dbname`,
  поставить `asyncpg` вместо `aiosqlite`.
- **Миграции**: сейчас `create_all` при старте; для прода — подключить Alembic.
- **FSM-хранилище**: `MemoryStorage` → `RedisStorage` (переживает рестарты).
- **Webhooks**: точка входа изолирована в `bot.py` — poll → webhook меняется локально.
- **Логи**: все фоновые задачи и сохранения отчётов пишутся в `logging`.

## Развёртывание на Ubuntu

1. Установите Python 3.11 и зависимости:

```bash
sudo apt update
sudo apt install -y python3.11 python3.11-venv python3-pip git
```

2. Склонируйте репозиторий и создайте виртуальное окружение:

```bash
git clone https://github.com/Ta1l/Duo_finance.git
cd Duo_finance
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

3. Настройте `.env`:

- `BOT_TOKEN` — токен от @BotFather.
- `DATABASE_URL` — например для SQLite `sqlite+aiosqlite:///./duo_finance.db`.
- `PROXY_URL` — если сервер не имеет прямого доступа к Telegram.

4. Запустите бота вручную:

```bash
source .venv/bin/activate
python bot.py
```

5. Для постоянной работы используйте `systemd`:

```ini
[Unit]
Description=Duo Finance Telegram Bot
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/Duo_finance
EnvironmentFile=/home/ubuntu/Duo_finance/.env
ExecStart=/home/ubuntu/Duo_finance/.venv/bin/python /home/ubuntu/Duo_finance/bot.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

Сохраните как `/etc/systemd/system/duo_finance.service`, затем:

```bash
sudo systemctl daemon-reload
sudo systemctl enable duo_finance.service
sudo systemctl start duo_finance.service
sudo systemctl status duo_finance.service
```

## Прокси для Telegram на российском сервере

- Используйте **SOCKS5-прокси** от проверенного провайдера, в стране, где Telegram не блокирован.
- Пример формата: `socks5://username:password@host:port`.
- Не используйте MTProto-прокси — для бота нужен SOCKS5, который работает на уровне HTTP/API.
- Покупайте прокси у надёжных поставщиков с низкой задержкой и гарантией работы именно для Telegram.
- В `.env` укажите `PROXY_URL`, например:

```env
PROXY_URL=socks5://user:pass@proxy.example.com:1080
```

Если прокси настроен, бот будет подключаться к Telegram через него автоматически.
